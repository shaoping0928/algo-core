# 神经元基座

一页规格：这套基座由什么组成、每一步算什么、每条规则从哪来，
以及哪些数字是测出来的。后面接任何新任务，都从这里实例化。

它不是一个神经网络框架，也不是语言模型。它是 **离散节点 + 稀疏有符号边 +
三个时间尺度上的状态 + 一个线性读出层**，全部学习规则是局部的（误差只回传一步），
只有 numpy，大约 200 行。

参考实现：`recall_world.py`（唯一带验收闸门的实例）。

## 0 目标（这一条决定所有验收标准）

这不是为某个任务设计的结构，而是一个**通用自拟合基座**：同一份代码、同一组原语，
靠拟合去适应不同的世界；结构本身可以增长，所以不受固定深度的限制。
参照物是深度学习网络，不是某个记忆模型——所以"在延迟回忆上多记几步"只是**一个**
测量，不是目标。

三个差异点，每个都必须有实测支撑，否则不算数：

```
1 最基础的深度学习   五个原语（节点/边/三个状态/线性读出），没有注意力、卷积、
                     embedding、层归一化。任何"为了适配自然语言"的结构都不进来。
                     证据：§80（150 行复现 60 模块栈）、§102（GPU 版仍是同一组原语）

2 规模是动态的       节点数不是超参，是运行时变量。
                     证据：§96-§99（8→128 节点，.593→.985；瞄准式发芽 86 节点）
                     反面证据：§102（只加宽不加结构，留出不动，因为表征秩坍缩）

3 监视自身并据此行动  系统每 N 步读自己的四个量，并按表选动作。
                     证据：§103（秩→增益、路由器熵→路径、使用率→剪枝、误差趋势→样本）
                     现状：信号都在测，但**控制器还没写**——这是当前唯一缺的部件
```

三条判据，按顺序，缺一条就不能叫通用：

```
1 任务无关   同一份代码、不改超参，能实例化到至少三类互不相似的任务
2 可表达     能拟合出需要内部状态的计算：延迟保持、计数、条件分支、状态机
3 可增长     能力不足时靠新增节点/边提升，而不是靠换结构或加专用模块
```

**"一定程度图灵完备"在有限网络上是什么意思**：固定节点数 + 固定边 = 有限状态机，
不是图灵机。要往上走只有一条路——让带子（存储）随需求增长，也就是判据 3。
这就是为什么节点分裂从"可选机制"变成必需项：它提供的是无界存储，而不是某个任务的技巧。

现状与差距：

```
需要的能力        现状                                    缺什么
保持离散值        soft + assoc 吸引子：d=32 .96，drive 噪声 .1 仍 .96   （已具备）
写入/保持开关      ——                                     没有门控 → 只能有一个寄存器
多个寄存器        ——                                     没有绑定（槽位 + 内容）
条件分支          ——                                     没有"按内容选路"
无界存储          分裂代码存在，但触发条件绑错量，从未真正运行   误差驱动的增长触发
组合与序列        ——                                     时间上的读写控制
```

所以优先级不是"把 d_max 从 32 推到 128"，而是：**门控（写/保持）→ 多寄存器绑定 →
按内容选路 → 增长**。每加一个，都问"它让基座能表达什么新的计算"，
而不是"它让某个任务的分数提高多少"。

## 1 五个原语

```
N   节点，只有"激活 / 不激活"和一个连续幅值
K   每个节点的入边数（稀疏，固定），边由 (源节点, 权重) 表示
S   输入维数（这里 8 个符号），通过固定随机映射 Pin 进入节点
A   每步活跃节点数（top-A，稀疏编码）
O   读出层：线性 + softmax，唯一的监督界面
```

没有层级、没有模块、没有注意力。判别力全部来自"哪些节点同时活跃"和"边有多重"。

## 2 一步的完整顺序（照这个顺序实现，顺序会改变结果）

```
1  驱动       drive_i = (1/√K) Σ_j w_ij · (1 + gain·r_ij) · h_j  +  (Pin·o)_i
2  激活       h_i = 1[i ∈ topA(|tanh drive|)] · tanh(drive_i)
3  节点状态   u_i ← (1−β)·u_i + β·h_i + σ_mem·ξ          ξ ~ N(0,1)
4  边状态     r_ij ← r_ij + α(1−r_ij)      若 h_j ≠ 0（该边刚被用过）
              r_ij ← (1−β_r)·r_ij          否则
5  读出       x = u（缓冲臂）或 x = h（默认）；p = softmax(W_o·x)
```

`topA` 是硬稀疏：只有幅值最大的 A 个节点保留，其余清零。它同时是容量上限和抗噪来源。

## 3 三条学习规则（全部局部）

```
读出    ΔW_o  = η · (y − p) · xᵀ
递归    g      = W_oᵀ (p − y)                    后活动误差，只有一步
        Δw_ij  = η · h_j · g_i − λ·w_ij
迹      tr_ij ← γ·tr_ij + h_j
        Δw_ij += η_T · tr_ij · g_i
```

要点：

```
没有 BPTT        g 由读出层一步回传，不跨时间
没有全局量       每个 Δw 只用突触前活动 h_j 和突触后误差 g_i
符号正确          Delta 规则，不是 Hebbian（用 p−y 而不是 p·y）
可裁剪            w 截断在 ±0.5；u/r/h 天然有界（tanh、top-A）
```

## 4 参数与实测效果

```
符号     含义                        实测作用
β        节点状态泄漏率，1/β = 记忆   容量决定量：β=.1 时 σ=0 → d=32 .96
                                       σ=.002 → d=32 .54   σ=.01 → d=16 .63
σ_mem    状态噪声                    只能靠噪声暴露"是否真在保持"
gain     边残留对驱动的增益          门槛量：2 → +1 步；6 → d=4；15 → d=8
α        一次使用带来的易化量        与 gain 共同决定残留峰值
β_r      残留衰减率                  决定易化能撑几步（.02 vs .005 差 ~1 步）
K        入度                        稀疏度；K=16 在这个规模够用
A        活跃节点数                  16 个符号用 A=32 足够；A 越小越抗噪、越难区分
η        学习率                      .03；再大读出层会震荡
λ        权重衰减                   1e-5，只防漂移
```

## 5 三个时间尺度（这是基座的核心结构）

```
快   h_i      ~1 步     输入消失就灭；容量 2 步的来源
中   r_ij     数步      路径记忆：刚走过的边更容易再走；打断/续接活动链
慢   u_i      10~30 步  值记忆：一个有符号的泄漏副本，供读出层解码
```

三者不是三个模块，而是同一组节点/边上的三条标量状态。它们的实测对照：

```
             容量      state@blank     失效方式
h 只有       2 步      0.80→0.03       输入一撤活动就灭
r 强易化     8 步      0.61 (d=4)      增益太大时锁死在错误模式
u 缓冲       ~20 步    0.00            噪声一大就漏光
```

`state@blank` = 最后一步静默时的 Σ|h|。它区分"真的在维持"和"一个痕迹被无噪声解码"，
所以任何记忆结论都必须带这一列。

## 6 结构侧：节点分裂

```
触发     每 SPLIT_EVERY 步，取累计|g|最大的活节点 i
新节点   找一个死节点 j（无空位时退休读出权重最小的活节点）
继承     src[j] = src[i];  w[j] = w[i] + N(0, 0.02);  W_o[:,j] = 0
```

新节点是"一个被轻微损坏的副本"，它从零读出权重开始自己找位置。

**实测（`sprout_world.py`，容量受限的预测任务，V=64，起始 8 节点，上限 128）：**

```
arm                        probe acc   alive
fixed                      .593           8
sprout（每 1000 步）        .671          38      事件太少，不是机制上限
sprout（每 200 步）         .985         128      真正跑到容量
prune only                  .609           8      不会低于 N0，等于空操作
sprout + prune（500）       .907          98      用 8 点精度换 30 个节点
```

三条结论：

```
1 生长确实买到能力（.593 → .985），但很贵：128 个"复制+扰动"的节点，
  才顶得上 32 个随机节点在稍易任务上的表现
2 剪枝不是能力来源，是容量调节：单独存在时无法触发，配合生长时用精度换规模
3 新节点继承的是"误差最大的节点"，所以它是噪声副本，不是新特征
   ——这是它效率低的原因，也是下一步该改的地方
```

在延迟回忆上仍未测（那里 w 本身不贡献，生长没有作用面）。

## 7 哪些是设计的，哪些是测出来的

**设计的（我们写的规则）**

```
β 衰减常数、gain 环路增益、α/β_r 易化参数、top-A 稀疏、线性读出、误差一步回传
```

**测出来的（不是推的）**

```
2 步       局部规则单独作用的天花板（readout == all，逐格相同）
8 步       边残留 gain=15：state@blank .61，活动真的在维持
~20 步     缓冲 β=.1 + 噪声 .01：状态为死，容量由 β 与噪声共同决定
0          递归可塑性对精度、对容量、对 state@blank 的贡献
0          资格迹、反向追踪、节点分裂的增量
```

**明确尚未有的**

```
吸引子（线吸引子/双稳态）：gain 增大能延长活动，但 d=32 掉到 .047，
即活动维持住了却锁在错误模式。要拿到稳定的吸引子，需要跨时间的信用分配
（BPTT 或等价物），这是开放项。
```

```
python recall_world.py 200 600 0
chance .125   d ∈ {1,2,4,8,16,32}

frozen         全 d = 机会水平               <- 闸门，不满足则整轮作废
readout        d≤2 .96，d≥4 = 机会水平       <- 被动容量 2 步
readout+umem   全 d .96                      <- 缓冲 + 纯读出即满容量

```

## 9 换任务怎么实例化

只需要两件事：

```
1 输入映射 Pin    任意 (N, S) 固定随机矩阵；S 是任务的输入维数
2 报告点         任务里必须有一步"要求输出"；误差只在这一步产生
```

其余不用改。如果任务没有明确的"报告步"，那么延迟信用分配问题不存在，
但也就没有"记忆"这件事可测——这正是一路踩过的坑（见 `docs/boundary.md` 的记忆节）。

## 10 失效条件（每条都实测过）

```
观测单射         无记忆映射就够，递归层看起来"没用"（世界闸门 g2 的教训）
没有噪声         泄漏积分器也能满分，容量被高估（d=32 的 .96 是假象）
增益不足         gain=2 只把静默期活动从 .80/.03 抬到 1.99/.16，多撑一步
增益过大         活动锁在错误模式，d=32 = .047，低于机会
臂名与代码脱钩   控制臂会悄悄变成实验臂（曾因此误报"递归编码必需"）
```

## 11 内置节点类型（E / I / F）

群体按索引一次划分，不再改：E 70% / I 20% / F 10%。类型不是学出来的，是原语的一部分，
与"层"无关——三者共享同一套边、同一个读出层。开关 `OMNI_TYPES=1`。

```
E  促进   残留（易化）只作用在 E 的出边上
I  抑制   I 群体的激活汇成一个除法池：drive ← drive / (1 + κ · pool)
           pool = Σ|h_I| / (A·FRAC_I)，按活跃数归一，不按群体大小
F  拟合   一条稀疏一次性联想记忆 M（与 w 同形状）：
           M ← (1 − δ)·M + η_f · h ⊗ h_src
           静默期把 recall 加回驱动：drive += (M · h_src).sum()/√K
```

实测（延迟回忆，200 episodes/d，同一符号序列）：

```
arm                d=1    d=2    d=4    d=8    d=16   结论
all                .960   .955   .135   .150   .145   基线
all+typed          .960   .950   .135   .150   .145   类型只改增益 → 零
all+typed+residue  .955   .950   .925   .665   .145   比不加类型更差
all+assoc (η_f=2)  .955   .955   .790   .225   .145   联想记忆真的动
all+assoc (η_f=10) .955   .955   .870   .300   .145   但 d=8 封顶
```

三条由测量得到的规则：

```
1 类型必须承载变量，不能只改强度
    "F 型 = 学习率×2" 时 FBOOST=5 与 1 逐格相同 → 完全无效
   "F 型 = 一次性联想 M" 时 d=4 从 .135 升到 .87 → 同一个名字，两种实现，差别在变量

2 抑制不是越多越好，因为失效模式不是发散
   κ=1 时 d=8 .665，κ=3 时 .575；d≥16 的失败是衰减，不是失控，没有东西可抑制

3 促进只作用在一部分边上等于主动削弱
   E 只覆盖 70% 的边：d=8 .740 → .665，静默期活动 9.19 → 5.47

参数    OMNI_TYPES OMNI_KAPPA OMNI_FBOOST OMNI_ETA_F OMNI_DECAY_F
臂      all+typed  all+typed+residue  all+assoc
```

**这一节的封顶是在硬稀疏（soft=0）下测的**：联想记忆 d=8 封顶 .30，加大 η_f 无效，
因为 top-A 一旦把活动清零，任何记忆都无法把它重新推过门槛。
把硬稀疏换成软阈值（§12）后，同一个机制直接到 d=32，所以这条限制属于阈值，
不属于类型。

## 12 门控与遗忘

`recall_world.py` 测"能保持多久"，`gate_world.py` 测"能不能控制写、忽略、擦除"。
门控信号**不进入驱动**，只作用于写入规则——否则读出层可以直接读门，测的就不是机制。

```
写入   写使能是锁存：门一开就一直重写，直到清除
       写一次就给 .011（d=32），每步重写给 .923 —— 保持靠复述，不靠快照
忽略   不写：状态精确为 0，靠读出层偏置报"空"
擦除   擦除信号把 M 和 h 同时清零：状态 33.5 → 0.0，准确率 1.000
遗忘   锁存保持 HOLD 步后失效，之后只剩衰减
       寿命 ≈ HOLD + 1/衰减率，两个旋钮都单调
```

实测（gate_world.py，9 类，机会 .111）：

```
arm              d=8    d=32    写/忽略/擦除 @32
frozen           .035   .100    .220/.000/.000
ungated          .505   .515    .462/.581/.514
gated            .755   .715    .670/.973/.286
gated+forget     .950   .955    .923/.973/1.000
```

三条设计上的必要条件（都不是调参能绕过的）：

```
1 门必须不可见       门进驱动时"忽略"能靠读门做对（.988，机制完全没参与）
2 状态为零也必须有说法 读出层没有偏置列时，擦除条件永远答不对
3 写使能是锁存        "写一次"不足以维持；每步重写才是保持
```

参数：`OMNI_HOLD`（锁存时长）、`OMNI_DECAY_F`（遗忘速率）、`OMNI_WRITE_ONCE`、
`OMNI_P_IGNORE`、`OMNI_P_ERASE`。

## 13 比较两个值：为什么必须有两个格子

`compare_world.py`。两个值先后到达，静默 d 步，报告 a>b 还是 b>a（机会 .5）。
同一基座、同参数、同节点总数，唯一差别是**寻址方式**：

```
shared   一个 600 节点群体，一个联想矩阵，两个值写进同一处
split    两个独立的 300 节点格子，各自有连线、联想和输入
         a 在 t=0 进格子一，b 在 t=1 进格子二，读出层看到两者拼接
```

```
arm      d=0    d=1    d=2    d=4    d=8    d=16   d=32      噪声 .05 三seed
frozen   .495   .565   .450   .500   .455   .445   .525
shared   .735   .675   .715   .720   .725   .750   .725      .635-.720
split    .895   .910   .910   .925   .920   .940   .930      .890-.930
```

三条读数：

```
1 分离不是只为记忆，是计算本身的要求
   d=0 时两个值都还在输入里，什么都不用记，共享群体 .735，分裂 .895
   单个密集吸引子无法把两个项表示得足够可分，线性读出层减不开它们

2 叠加不是零，但很脆
   共享在 d=0 有 .735（远高于 .5），说明两个模式没有简单互相覆盖
   加噪声后掉到 .635-.720；分裂臂不动（.89-.93）

3 判据：H4（分裂 d=8 ≥ .85）全程成立（.90-.93）
   H3（共享 ≤ .70）无噪声时未达标（.725），加噪声达标（.635-.670）
   照实报，不回调阈值
```

这个任务不需要非线性读出：`value(a) − value(b)` 对两个 one-hot 码是线性的，
所以线性头就能做比较。正因为如此，结果只分离出"绑定"这一个变量。

**它还没有做到的**：路由是固定时间表（a 在 t=0，b 在 t=1），系统不会解码地址，
所以不能被告知"写进哪个格子"，只能按固定顺序接收。两项、固定顺序、一次比较——
这算一个计算，但还不是机器。

## 14 寻址：槽位决定写哪里，不看到达顺序

`address_world.py`。两个值以随机顺序到达，每个带一个槽位信号（1 或 2，不进入驱动），
报告"1 号格里是什么"。机会 1/8。

```
arm      d=1    d=2    d=4    d=8    d=16   d=32   两种顺序 @d=8
frozen   .100   .150   .160   .110   .160   .155   .102 / .118
time     .460   .470   .445   .460   .445   .510   .439 / .480
addr     .935   .935   .950   .955   .945   .955   .969 / .941
```

噪声 .05、三个种子：addr 每个 d 都在 .925-.965，两种顺序 .934-.972；time .41-.49。

**一个预测对得巧、理由错了**：我以为 time 臂会在一种顺序上高、另一种近零。
实际两种都只有 .44-.48。原因是读出层是一个线性头、在两种顺序上联合训练——
同一状态在两种顺序下对应不同答案，它必须平均两个不相容的映射，所以两种都差。
失败不是"一半对"，而是"这个映射不是函数"。

三件事被确定：

```
槽位被用到了   .94-.97，与固定顺序时相同
槽位没被读到   它不进驱动，答案不可能来自它
寻址与保持分离 同样的格子、同样的联想，只有写入目标不同
```

**还不是机器**：槽位固定两个、地址是外部给的标量、两次寻址写入不能被组合成程序。

## 附录 A 规则层：激活是"检验"而不是"投影"的节点

前面五条原语里，节点做的是投影（`tanh(Pin·x)`），读出是线性的。这一层补的是规格里
明确列为缺口的那一项——"组合与序列"。它不引入新的原语类型：**仍然是一个节点，
只是它的激活值是一次方差分解的结果**，而不是一次投影。

```
不变量节点   某量的散布在组内消失  →  它不是它以为的那组变量，而是另一组
             当它成立时，节点同时带着"它对允许变量的依赖"，由组内最小二乘读出
决定性节点   某结果在组内是常数    →  这组变量充分
```

两者的判别标准是同一条：**组内散布 / 总体散布**。不变量成立时是机器精度，不成立时
不是"弱"，是"没有"。这就是"规则"和"拟合"的区别：拟合永远近似，不变量要么精确、
要么不成立。

参考实现：`substrate_rules.py`（`RuleBook`）；验收脚本：`rule_mainline.py`。

3  决定性检验拒绝了二变量集合并接受了三变量集合，这正好等于死亡的真实结构：

### A.2 两个必须一起说清的边界

```
1  变量必须在表里。若观测里没有 vy，那么对可见变量做任何不变量检验都得不到这条规则
   —— 那是接口问题（§142 的 7 帧、§160 的时标），不是检验的能力问题。

2  结果零方差时决定性检验是空真的。"没有死亡"的数据里，任何变量集都"决定"死亡，

```
### A.3 接进基座自己的循环

规则层现在是基座的一部分，不是外挂：`live_core.Live` 新增一个**信号**和一个**动作**。

```

动作   scan     = 检验候选不变量，保留成立的
触发   行数够 + rule_err > thr + 预算未用完

原有四个信号（rank / held / gap / spread）和三个动作（gain / route / prune）**一行未动**。

验收（`rule_loop.py`，2000 行动力学数据边读边跑）：

row 1200   held 2   residual 3.9e-16    scans 1     ← 1000 行扫描后

2  它不干扰既有读出：R2 是逐位比较，不是"统计上差不多"。新动作只增加了一条日志。

3  触发条件本身是设计出来的量：行数、覆盖率、阈值、预算。和 §104-§117 的监视器动作一样，

接线时踩到两个实现错误，记在这里因为它们都是同一种：

```
1  step 里只把 row 存进残差窗口，没有喂给 RuleBook.observe → scan 看到空表

### A.5 规则层 → 策略层：系数从规则里掉出来

前面 A.1-A.4 里规则层只解释世界。这一步把它接到动作上，**不给任何手写系数**。
`rule_policy.py`：

```
1  从带限数据里恢复两条不变量（不给形式）
     dy = -0.001600 +1.000000*vy +0.020000*a
     dv = -0.001600 +0.020000*a

2  用这六个数把 12 步展开（第一步用动作，之后滑翔）
     因为展开是仿射的，两个终点之差是一个常数，
     所以"取离缺口中心更近的那个"退化成一条线性阈值

3  阈值由规则算出，不是写进去的
     flap iff (gc - y) - 1.200000*vy10 > -0.004800
```

**1.200000 是算出来的。** 它等于 `H/10`，因为每帧的速度直接加到位置上；常数 −0.0048
等于 `-g·H(H+1)/2 + H·F/2`。

```
策略                                       存活
  从规则推出，瞄准当前管子                   782.9   （= §145 探针的 783）
  从规则推出，瞄准 t+12 时的那根管子           1133.1  （= §152 的规划器）
  手写规则（1.2 和 0.1 是我敲进去的）          1200.0
```

三条读数：

```
1  接缝闭上了。策略的**形状**（在 dy 与 vy 上的线性阈值）和**系数**（1.2）都来自规则层，
   不是来自我。这是这条线上第一次"策略系数不是人为给定"。

2  与规划器完全一致：1133.1 对 1133.1。也就是说，展开规则得到的动作与跑 12 步 rollout
   得到的动作是同一个——规则层没有损失信息。

3  差的 67 帧（1133 对 1200）在**常数**上：规则推出的中点是 -0.0048，而手调的 0.1 更好。
   原因是碰撞判定用的是管壁的位置而不是缺口中心，理想中点不是最优阈值。这是几何，
   不是规则——规则那一半已经精确了。
```

仍然在系统之外的，只有一样：**目标**。缺口中心是任务给的，不是规则层推出来的——
这正是 §160 测到的那个接口量（目标的时间尺度取不出来）。
### A.6 第七个算子：自己提出组合，而不是检验我点名的组合

规则层（A.1）检验的是**我给的候选量**。这仍然是我在选特征。这个算子把选择也交给系统：
它在**线性组合**里搜索，报告那些被其余变量完全决定的量。

```
做法   每个变量轮流当目标，其余变量（含常数项）当预测子，
       子集从 1 个到 4 个，要求最大残差 ≤ 1e-9 × 尺度
输出   目标 = c0 + Σ ci·预测子，以及残差
含义   目标不依赖预测子之外的任何东西，且系数就是机制的常数
```

在 `(y2, y, vy, a)` 上搜索的结果（3473 行，没有任何提示）：

```
y2  = -0.001600 +1.000000*y +1.000000*vy +0.020000*a   残差 6.7e-16
y   =  0.001600 +1.000000*y2 -1.000000*vy -0.020000*a  残差 1.1e-15
vy  =  0.001600 +1.000000*y2 -1.000000*y -0.020000*a   残差 1.7e-15
a   =  0.080000 +50.000000*y2 -50.000000*y -50.000000*vy 残差 1.1e-13

(vy2, vy, a)
vy2 = -0.001600 +1.000000*vy +0.020000*a               残差 1.9e-16
vy  =  0.001600 +1.000000*vy2 -0.020000*a              残差 2.4e-16

对照：把 y2 打乱后重搜  →  找到 0 个组合
```

四条读数：

```
1  它自己提出了特征。系数 1.000000 和 0.020000 是重力与挥翅冲量，残差到 1e-16；
   正向和反向映射都被找了出来。

2  第四个结果值得单列：**动作 a 可以被 (y2, y, vy) 精确解出**（系数 50）。
   也就是说，状态转移里完整编码了"我刚做了什么"。这是自模型（self-model）的种子：
   系统能从世界的变化里读出自己的动作，而不需要内部记录。

3  对照组找到 0 个，说明搜索不会在噪声里造出组合。这一点必须报，否则"找到规则"
   和"找到巧合"分不开。

4  这个算子的输出可以直接喂给规则层：它给出的组合就是 A.1 里的候选量。
   两级结构因此闭合：**先提议组合，再检验组合在哪些变量上是不变的。**
```

它和 A.1 的分工：

```
A.6 提出      哪些线性组合成立（不依赖谁）
A.1 检验      成立的那个组合，对哪些变量是不变的，依赖长什么样
A.5 使用      把成立的不变量展开，得到策略
```
### A.7 第八个算子：非线性基 + 前向选择

A.6 只在原始列的线性组合里搜。这一层把候选换成**基函数**，并用前向选择在 70/30 划分上
挑最小的组合：

```
v,  v^2,  |v|,  sign(v),  v*|v|,  v*w,  v*|w|,  |v|*w      对每个原始量 v 和每一对 (v,w)
```

两个世界，同样的列，只改物理（`FL_DRAG`）：

```
                           线性基残差      扩展基残差
线性世界   vy2                3.9e-16        4.2e-16
二次阻尼   vy2                4.97e-03       6.6e-16
```

恢复出来的拖曳项：

```
vy2 = -0.001600 +1.000000*vy +0.020000*a -8.000000*vy*|vy|
                                       ^^^^^^^^^^  与 FL_DRAG = 8.0 一致
```

三条读数：

```
1  线性基在二次世界不成立（4.97e-3），扩展基精确（6.6e-16）。判别标准没有变：
   "组内散布/总体散布" 或 "验证残差"，成立就是机器精度，不成立就是一个明确的数。

2  恢复的系数量级正确：-8.000000 对 FL_DRAG = 8.0。这不是拟合出的近似数，是机制常数。

3  线性世界里扩展基也停在 4.2e-16，并且给多余项 0 系数——加基不会凭空造出结构。
```

接线时踩到的两个错误（都是同一类）：

```
1  基里没有 v*|v| 自项。二次阻尼正好需要它，所以第一次跑出来的残差是 7.6e-4
   ——"差一点"是错的候选集，不是"这个世界的规律难学"。
2  前向选择没有把已选特征从池子里去掉，于是把同一个特征选了两次（系数 0.5+0.5）。
   残差看不出问题，但读出来的系数是错的。
```

一个诚实的边界：

```
y2 在二次世界里仍然不是精确的（4.99e-03），因为 y2 = y + vy2 需要的是**更新后**的速度，
而基里只有更新前的 vy。这不是搜索失败，是输入里缺那一列。
它正好说明下一层要加什么：**延迟 / 更新后的量**（把 vy2 作为列带进来）。
### A.8 第九个算子：延迟量作为候选列

世界：动作 **3 帧之后**才生效

```
y'  = y + vy
vy' = vy - g + F*a(t-3)
```

```
用 (y, vy, a) 搜索                    残差 1.48e-02     不成立
再加上 a(t-1..t-3) 作为候选列           残差 4.5e-17
  vy' = -0.001600 +1.000000*vy +0.020000*a_lag3
```

```
D1  没有延迟列时，最好的基也停在明确的正残差     ok（1.48e-02）
D2  加上延迟列后精确                          ok（4.5e-17），系数 1.000000 与 0.020000
D3  它选的是 a_lag3，不是 a_lag1 或 a_lag2      ok
```

三条读数：

```
1  搜索本身没有变聪明，它拿到了机制真正用的那个变量。这就是"提供更多基础算子带来更多信息"
   的准确含义：不是让搜索更强，是让候选集里有对的列。

2  这正是基座三个时间尺度（u 漏积分 / M 一次性绑定 / r 边残留）存在的原因——
   它们的作用就是让"延迟的量"在表里有一个列。在此之前它们只有状态语义，没有算子语义。

3  D3 是关键判别：三条延迟列同时在场，搜索挑中了正确的那一条。若它挑错或挑中三条，
   那说明"精确恢复"只是过拟合（6000 行、4 个候选时不会，但这条必须报）。

同时做了一次去重：搜索算子现在只有一份实现，在 `substrate_search.py`
（`basis` / `greedy_determine`），A.6 与 A.7 的验收脚本都从它导入。去重之后 A.7 的
残差还从 6.6e-16 降到 9.0e-17——因为新的前向选择不会把同一个特征选两次。
### A.9 漏积分不是延迟线：基座自己的 u 拿不到那个滞后

A.8 里 `a(t-3)` 是我直接给的列。这一层换掉它，只给基座自己的状态：

```
u_k(t) = (1 - beta_k) u_k(t-1) + beta_k a(t)        beta in (0.5, 0.2, 0.1, 0.05, 0.02)
```

世界不变：`vy' = vy - g + F*a(t-3)`。

```
状态来源                          残差        被选中的特征
没有状态 (y, vy, a)               1.48e-02    vy, y*a, |vy|*a, sign(y)
一个漏积分 u(0.2)                 1.48e-02    同上（一个 u 都没被选中）
两个 / 三个 / 四个 / 五个 u        1.48e-02    同上
真正的移位寄存器 a(t-1..t-3)       4.51e-17   vy, a_lag3

把整个 u 组一并线性拟合（测张成，不是逐个加法）
  1 个 u   1.64e-02
  2 个 u   1.99e-02
  3 个 u   1.98e-02
  4 个 u   2.09e-02
  5 个 u   2.23e-02
```

四条读数：

```
1  一个漏积分不够，一组也不够。残差停在 1.5e-2，而且 u 组越大验证残差越差（过拟合）。
   这不是"没调好 beta"，是结构：有限个指数核的张成里没有 delta。

2  原因是数学的。u_k 是历史的指数加权和，f_k(j) = beta_k(1-beta_k)^j；要取出 a(t-3)
   需要一个在 j=3 处为 1、其余为 0 的线性泛函，而那不在任何有限个指数核的张成里。
   要表示延迟 k 步，需要 **O(k) 个独立状态**（移位寄存器），不是一个时间常数。

3  这和 §91 的寻址仪器是同一句话的两面：**保持与寻址可分离**。
   u 有保持（能记住多久），没有寻址（不能问"第 3 步的那个"）；
   移位寄存器是"按位置寻址"。基座目前只有前者。

### A.10 记忆让一个本身不充分的状态变得充分

### A.16 噪声下的判据：数模态，sigma 由同一次拟合给出

`substrate_modes.py`。上一节的判据在第一条噪声上就失效：1200 个样本 → 1200 个不同取值。

### A.20 均值器：两种均值的反演代价不同

库原来没有滑动平均。加上之后，它和指数均值在"产生"上都精确，在"反演"上差一个数量级：

```
M1  从驱动产生 ma9         2.21e-16
    次优 leak0.1           7.31e-02

M2  从 ma9 反演驱动
    [m(t), m(t-1)]                        3.49e-01     做不到
    w*(m(t)-m(t-1)) + x(t-9)              5.55e-16     精确，但需要 9 步前的目标

leak      x(t) = (u(t) - (1-b)u(t-1))/b          只需要自己的上一步    O(1)
ma_w      x(t) = w*(m(t) - m(t-1)) + x(t-w)      需要 w 步前的目标     O(w)
```

等有效滞后时抗噪一样：

```
ma9       实测增益 0.320   预测 1/sqrt(9) = 0.333        有效滞后 4.0
leak0.20  实测增益 0.322   预测 sqrt(b/(2-b)) = 0.333    有效滞后 4.0
```

**差别不在抗噪，在反演代价。** 选哪个是结构问题，不是滤波效果问题。

仪器注意点：把 `[m, m_prev, x(t-9)]` 直接做最小二乘，残差是 4.06e-3 而不是 0，因为三列
近似共线；逐字写出代数形式才是 5.55e-16。**关系成立不等于最小二乘能把它解出来。**

### A.21 噪声是从哪来的：三种，量纲不同

先回答"这个噪声是哪来的"。这一路所有 sigma 都是**注入的**，不是测到的：

```
模型侧（A.16/A.19）     注入 iid 高斯，加在一个通道上；sigma 是旋钮
策略侧（A.11）          不是高斯：待定比特被翻转，离散、结构化
内部状态（A.10）        唯一一处内部噪声：OMNI_UMEM_NOISE 加在 u 上
系统本身                确定性（没有硬件抖动、没有随机性）
```

所以"系统对噪声的处理"必须拆成三件事，单位都不同。

#### 一、注入高斯的结论取决于谱

同一个 marginal sigma，只改相关性：`n(t) = rho*n(t-1) + e(t)`，e 缩放使 std(n) = sigma。

```
rho    预测增益   实测 rms/sigma   裕度
0.00    13.45      13.67          4.0     <- 白噪声，最坏情况
0.30    11.27      11.41          4.7
0.60     8.54       8.63          6.2
0.80     6.08       6.14          8.6
0.90     4.36       4.41         11.9
0.95     3.16       3.24         16.1
0.98     2.14       2.35         22.3
0.99     1.67       1.93         27.1

闭式  sqrt(1 + (1-b)^2 - 2(1-b)rho) / b      0 <= rho <= 0.99 全程对上（差 <= 10%）
```

**白噪声是微分器的最坏输入。** 同一个 sigma，慢漂移的危害小 7 倍，裕度从 4.0 升到 27.1。
所以 A.19 的"sigma < 3e-3"是**最坏情况**的读数：对量化/抖动这类高频误差成立，对漂移过于悲观。

一个退化情形的记录：rho = 1 时 e 的方差按 sqrt(1-rho^2) 缩到 0，噪声变成常数偏移，被截距
吸收，残差为 0——那不是算子的功劳。所以表只到 0.99，闭式的极限是 1.0（对"电平"的响应）。

#### 二、控制问题的"噪声"不是高斯

A.11 里杀死策略的是**待定比特翻转**：离散、结构化、不平均掉。2% 就吃掉 95% 的分数。
高斯噪声在同样量级下温和得多，因为策略对"均值对、方差大"还有容忍。
**在策略那一侧用 sigma 去测是单位错了；已经测对的单位是 bit flip。**

#### 三、真正顽固的是模型偏差

```
噪声项     增益 * sigma        随 sigma 长大，会被平均掉
结构偏差   0.113 / 0.340       不随 sigma 变，也不平均掉
```

A.19 的阶梯里两者同时在动。**偏差不会被平均掉，所以它是天花板；噪声只是斜坡。**
这条线上所有 1e-16 的精确都建立在"列是对的"上；列一旦不对（A.15 的共线、A.20 的 4.06e-3），
拟合就给不出真关系。

#### 能说与不能说

```
能说    对白噪声的敏感度有地平线（A.16/A.19），且随谱变化 7 倍（A.21）
能说    对结构化比特错误的敏感度是零容差（A.11）
不能说  "系统有多少噪声" —— sigma 是注入的
不能说  "带噪观测下的系统表现" —— 组合（噪声 -> 估计 -> 策略）一次没跑过
```
### A.22 适应：它会换列，但不知道自己信错了

A.19 只测了"某个固定噪声下选什么"。这一节测"噪声变了它跟不跟"。同一个仪器：滑动窗口
（W=2000、每 100 步重拟合一次，18000 步，切换点在 6000 和 12000）、取最小残差。

```
arm A  噪声 0 -> 5e-2 -> 0，世界不变
       稳态选择   unleak0.1 / unleak0.2 / unleak0.1
       翻转率     0% / 2% / 2%
       回到干净态 1500 步

arm B  世界的 beta 0.1 -> 0.3 -> 0.1，库是粗的（没有 0.3）
       稳态选择   unleak0.1 / unleak0.2 / unleak0.1     <- 落在最近的成员
       滞后       进 200 步，出 1900 步

arm C  同样的切换，库里加了 0.3
       稳态选择   unleak0.1 / unleak0.3 / unleak0.1     <- 落在真值
       滞后       进 1000 步，出 1900 步
```

四条读数：

```
1  它会适应，而且不用任何专门机制。判据是固定的，变的是数据。滞后 ~ W。

2  适应的分辨率 = 库的分辨率。真值 0.3 而库里没有 0.3 → 稳定落在 0.2；加进去就落在 0.3。
   这不是数据不够，是候选集不够——和 A.8 的"候选集里要有对的列"是同一条。

3  噪声下它会"自信地错"。sigma=5e-2 时固定点是 unleak0.2（真值 0.1），翻转率只有 2%。
   不是摇摆，是锁在一个更粗的结构上，而且没有任何读数提示它错了。

4  进得快、出得慢。进 200-1000 步，出都是 1900 步（≈ 整个窗口）。
   干净态里"对的"成员是精确的，任何污染都让它输；混合态里"错的"成员只要稍微更合适就赢。
   所以它忘记慢、采纳快——一个滞后性不对称。
```

第 4 条里有个反直觉的细节：

```
粗库（无 0.3）进 200 步，细库（有 0.3）进 1000 步。
因为粗库有个"折中成员" 0.2，混合窗口里它比 0.1 和 0.3 都更贴合，所以更早翻过去。
代价：粗库快而错，细库慢而对。这是适应的"速率-正确"取舍，可测。
```

准确的结论：

```
有    选择层的被动适应：随噪声和世界变化自动换列，滞后 ~W，稳定（翻转率 2%）
有    分辨率 = 库的间距；加候选就能提高（实测 0.2 -> 0.3）
没有  任何 sigma_hat 驱动的动作：不弃权、不改平滑、不改预判长度、不调窗口
没有  退出的机制：锁在错误结构上时，没有任何读数说"这里不可信"
没有  策略侧的适应：那边是零容差（A.11）
```

**它适应的是"哪一列更合适"，不是"我该不该信"。** 前者是选择，后者需要 A.19 缺的
那个裕度/下限读数。
### A.23 基建对学习器的契约：状态够不够

这一节不写策略，只问一件事：交给学习器的状态充不充分（马尔可夫）。判据还是残差和构造反例。

```
状态转移（预测 vy'）
  (y, vy, a)                        残差 9.55e-03     ← 延迟的冲量不在状态里
  (y, vy) + pending 队列            残差 1.63e-16     ← 充分
  (y, vy) + pending + 5 个算子       残差 1.80e-16     ← 算子不改变充分性
```

任务本身（"下一帧会不会死"）也是构造反例判的：

```
A  y=.50 vy=0 pending=(0,0,0)  管子 0.50 外，缺口 0.00  -> 不死
B  y=.50 vy=0 pending=(0,0,0)  管子就在身上，缺口 0.30   -> 死
```

同一个 (y, vy, pending)，结果不同 → 距离和缺口是任务状态的一部分。

仪器注意点：死亡判据是"两个阈值与绝对值的合取"，线性探针只能拿到 0.14–0.16 的死亡召回。
**关系成立不等于回归找得到**（A.20 共线之后第二次）。

基建契约：

```
给学习器    (y, vy, pending 队列, 距离, 缺口)      充分，测过
可选信号源  id/d1/d2/leak/unleak/ma               不改变充分性
自检判据    残差、决定性、基数/模态                用来判断"我给的列对不对"
不给        动作、预判长度、分区规则                那是学习器的
```
### A.24 深度、门控、积分：只有层间的非线性值钱

**差分的另一半是积分。** 它是一个精确的逆对：

```
I(d(x)) - x     2.78e-17        精确（d1 保留第一个样本）
d(I(x)) - x     5.68e-14        t >= 1；t=0 时为 0，即丢一个样本 = 积分常数
纯积分对白噪声的增益 sqrt(T) = 75.9（T=6000）-> 无界，不能用
库里能用的积分是 leak（直流增益 1），它的逆是 unleak
```

叠加几层值不值，取决于层间有没有非线性（同一个输入、同一个目标、三套信号）：

```
目标                         depth 1    depth 2    depth 2 + 整流
线性（驱动本身）               0.000      0.000      0.000
非线性（两个事件同时发生）       0.098      0.098      0.000
```

**线性的叠加是重新参数化；整流/门控夹在层间才产生新信息。** 而门控本来就在基座里。

深度有上限，测出来是"合取元数"：

```
2 元合取   0.194 (depth 1) -> 0.000 (depth 2)
3 元合取   depth 3: in-sample 0.080, hold-out 0.224   ← 不闭合，且 512 列过拟合 4200 行
```

所以稠密读出下可用深度是 **2**（8^2 = 64 信号/节点）；深度 3 只在稀疏读出下考虑。

门控的判据不是强度，是冗余：

```
按强度（保留前 50%）   保留 0-4 和 5，丢掉 10    <- 10 安静但唯一，信息丢了
按冗余（独立子集）     保留 0-4 和 10，丢掉 5-9  <- 信息没丢，省 50%
```

计算量 `8^depth`：8 / 64 / 512 信号每节点。门控是必需品，不是优化。
### A.25 电容：u 就是 RC 低通，每节点容量不需要

```
beta    tau=1/beta   t63 实测   DC 增益   脉冲衰减 / beta(1-beta)^t
0.50      2.0          1        1.0000        1.000000000000
0.20      5.0          4        1.0000        1.000000000000
0.10     10.0          9        1.0000        1.000000000000
0.05     20.0         19        1.0000        1.000000000000
0.02     50.0         49        0.9997        1.000000000000

充电：beta=0.1 时 20 步到输入的 0.878
```

**DC 增益 1、时间常数 1/beta、脉冲精确指数衰减**：u 是接地电容串电阻，一个 RC 低通。

每节点自己的容量要不要？不要。可达的时间常数由库的间距决定：

单个 beta=0.1     只在 beta_w=0.1 精确（6.24e-16），离开它退化到 0.08-0.74

### A.26 二元组：电容给"前一个"，乘积给"关联"

二阶流（下一个 = 当前 + 前一个 mod 8），上限 0.912：

```
beta   一步后残留   acc(h)   acc(h,u)   acc(h,u,h*u)
0.50      0.500      0.136     0.172       0.897
0.30      0.300      0.136     0.204       0.836
0.20      0.200      0.136     0.248       0.763
0.10      0.100      0.136     0.265       0.614
0.05      0.050      0.136     0.253       0.492
0.02      0.020      0.136     0.210       0.363
```

三条读数：

```
1  只用当前强度约为机会（0.136）：二阶规则不在 h 里
2  h + 尾巴 0.248：信息在了，但线性读出只能"相加"，不能"组合"
3  再加两两乘积 0.897（beta=0.5）：乘积就是"两个节点同时高"，即关联
```

**顺序由 h/u 的分块提供（现在 vs 残留），它的可靠度由电荷比 1/(1-beta) 决定**：
2.00 / 1.25 / 1.11 / 1.02 对应 beta = 0.5 / 0.2 / 0.1 / 0.02。这就是 A.9 的同一句——
漏积分是保持，不是位置。

为什么必须是乘积？因为规则是一张表，而可加读出的秩有限：

```
一阶流的切片奇异值   [1.000  0.034  0.025  0.020 ...]   有效秩 1 -> 可加就够（0.861）
二阶流的切片奇异值   [1.000  0.921  0.909  ...  0.868]   满秩   -> 必须交互项（0.248 -> 0.897）

可加读出 = a(当前) + b(前一个)，切片秩 <= 2；表有 S*S 格点，可加只有 2S 个参数
```

所以"要不要乘积"可以事先判断：**看目标表切片的秩是否超过 2。**
### A.27 稀疏边：边数 = 可达转移集，不是 S*S

```
流 A  一阶循环        发生  8 / 64 个转移   稀疏 8 特征 1.000   全乘积 64 特征 1.000
流 B  二阶（和 mod 8） 发生 12 / 64 个转移   稀疏 12 特征 1.000  全乘积 64 特征 1.000
```

**二阶规则也只走 12 个格子**，因为确定性规则生成的是轨道，不是全表。节省 5.3–8 倍而无损。

样本代价不变：

```
前 200 步：每个可达对被看到 16-17 次 -> 两种基都到 1.000
前 400 步：33-34 次 -> 同样 1.000
一个对只需要被看到一次；稀疏只影响"存多少"，不影响"学多快"
```

这是"文本要 S*S"那条的解法：不可行的只是"全外积"这个实现，稀疏边是它的可行替代，

.147 抬到 .713。

  等价于给每个节点一组 bank（A.25），真正的可调量是 bank 的间距。

直接用积分 int    不加
  白噪声增益 sqrt(T) 无界；有界的版本是 leak，已经在库里。

冗余门控           保留（但它是计算策略，不是能力）
  按冗余丢节点，省 50% 且不丢信息；按强度会丢掉安静但唯一的节点。
```

关于"合取"的一个诚实修正：`substrate_conjunction.py` 里两个二值指示量的合取，加性读出
本来就排序正确（w+b 的最大点就是 w=b=1），所以那个测试**不能**证明乘积节点有用；它证明的
是"对二值输入，合取不需要乘积"。乘积真正需要的条件是 A.26 的秩判据。
